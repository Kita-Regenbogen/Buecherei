Kita-Bücherei einrichten

Einmal einrichten (ca. 45 Minuten), danach läuft die App ohne Claude: Eltern öffnen sie ohne Anmeldung, das Team meldet sich mit E-Mail und Passwort an.

A · Einrichten (einmalig)

Die Bezeichnungen in Firebase und GitHub können je nach Spracheinstellung leicht abweichen.

  1. Firebase-Projekt anlegen

    1. Öffne console.firebase.google.com und melde dich mit dem Google-Konto der Kita an.
    2. „Projekt erstellen“ → Name z. B. kita-buecherei → Google Analytics ausschalten → „Projekt erstellen“.
    3. Der kostenlose Tarif („Spark“) reicht. Eine Zahlungsmethode ist nicht nötig.

  2. Anmeldung mit E-Mail einschalten

    1. Links unter „Build“ bzw. „Erstellen“: Authentication → „Jetzt starten“.
    2. Bei den Anbietern „E-Mail/Passwort“ wählen, den ersten Schalter aktivieren, „Speichern“.
    3. Optional: Reiter „Vorlagen“ → Vorlagensprache auf Deutsch stellen (betrifft die Mail bei „Passwort vergessen“).

  3. Datenbank anlegen und schützen

    1. Links: Firestore Database → „Datenbank erstellen“.
    2. Standort: europe-west3 (Frankfurt) – das lässt sich später nicht mehr ändern.
    3. „Im Produktionsmodus starten“ → „Erstellen“.
    4. Oben den Reiter „Regeln“ öffnen, den vorhandenen Text komplett löschen, den Text unten einfügen und „Veröffentlichen“ tippen.
    rules_version = '2';

// Kita-Bücherei – Sicherheitsregeln
// Eltern (ohne Anmeldung): dürfen nur die Bücherliste und die Einstellungen lesen.
// Team: angemeldet und in der Sammlung "staff" eingetragen (Konten legt die Leitung an).
// Leitung: wie Team, zusätzlich darf sie Zugänge (staff) verwalten.
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() {
      return request.auth != null
        && request.auth.token.email != null;
    }
    function staffPath() {
      return /databases/$(database)/documents/staff/$(request.auth.token.email.lower());
    }
    function isStaff() {
      return signedIn() && exists(staffPath());
    }
    function isLeitung() {
      return isStaff() && get(staffPath()).data.role == 'leitung';
    }

    // Bücher und Einstellungen: alle dürfen lesen, nur das Team schreiben
    match /books/{bookId} {
      allow read: if true;
      allow write: if isStaff();
    }
    match /settings/{docId} {
      allow read: if true;
      allow write: if isStaff();
    }

    // Kinder und Ausleihen: nur das Team
    match /kids/{kidId} {
      allow read, write: if isStaff();
    }
    match /loans/{loanId} {
      allow read, write: if isStaff();
    }

    // Zugänge: das Team darf die Liste sehen, nur die Leitung ändern.
    // Jede angemeldete Person darf prüfen, ob sie selbst freigeschaltet ist.
    match /staff/{email} {
      allow get: if signedIn() && email == request.auth.token.email.lower();
      allow read: if isStaff();
      allow write: if isLeitung();
    }
  }
}

  4. Zugangsdaten in config.js eintragen

    1. Oben links auf das Zahnrad → Projekteinstellungen → unten bei „Meine Apps“ auf das Symbol </> (Web).
    2. Name Kita-Bücherei eingeben, „Firebase Hosting“ nicht anhaken, „App registrieren“.
    3. Es erscheint ein Code mit const firebaseConfig = { apiKey: "…", … }.
    4. Öffne config.js mit einem einfachen Texteditor (Windows: „Editor“, Mac: „TextEdit“ im Menü Format → „In reinen Text umwandeln“) und trage die sechs Werte zwischen die Anführungszeichen ein: apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId. Speichern.

    Die Werte sind kein Geheimnis – geschützt werden die Daten durch die Regeln aus Schritt 3.

  5. App ins Internet stellen (GitHub Pages, kostenlos)

    1. Auf github.com ein Konto mit der Kita-E-Mail anlegen. Der Benutzername steht später in der Adresse, z. B. kita-regenbogen.
    2. Oben rechts „+“ → „New repository“ → Name buecherei → Public → „Create repository“.
    3. Auf „uploading an existing file“ klicken und alle Dateien aus dem Ordner hineinziehen (index.html, config.js, manifest.webmanifest, icon-192.png, icon-512.png, firestore.rules) → unten „Commit changes“.
    4. Im Repository: Settings → Pages → bei „Source“: „Deploy from a branch“ → Branch main, Ordner / (root) → „Save“.
    5. Nach 1–2 Minuten ist die App erreichbar unter https://BENUTZERNAME.github.io/buecherei/

    Statt GitHub geht jeder Webspace, der HTTPS kann – z. B. ein Bereich auf der Website des Kirchenkreises, wenn die IT einverstanden ist. Einfach alle Dateien in einen Ordner hochladen.

  6. Adresse in Firebase freigeben

    1. Firebase → Authentication → Reiter „Einstellungen“ → „Autorisierte Domains“ → „Domain hinzufügen“.
    2. Eintragen: BENUTZERNAME.github.io (ohne https:// und ohne /buecherei).

  7. Die erste Leitung freischalten

    1. Firebase → Authentication → Reiter „Nutzer“ → „Nutzer hinzufügen“ → E-Mail und ein Passwort für die Leitung eintragen → „Nutzer hinzufügen“. (Steht die Adresse dort schon, diesen Punkt überspringen.)
    2. Firebase → Firestore Database → Reiter „Daten“ → „Sammlung starten“ → Sammlungs-ID staff → „Weiter“.
    3. Dokument-ID: dieselbe E-Mail-Adresse in Kleinbuchstaben, z. B. leitung@beispiel.de (nicht „Automatische ID“). Feld: role, Typ „string“, Wert leitung → „Speichern“.
    4. Die App öffnen → oben „Team-Anmeldung“ → mit dieser E-Mail und dem Passwort anmelden. Oben steht jetzt „Angemeldet: Leitung“.

    Ab jetzt legt die Leitung alle weiteren Konten direkt in der App an: „Einstellungen & Team“ → E-Mail und Start-Passwort → „Konto anlegen“. Die App zeigt die Zugangsdaten zum Weitergeben. Jede Person setzt danach unter „Konto“ ein eigenes Passwort. Bestätigungs-Mails gibt es nicht – das umgeht Probleme mit Outlook und Dienst-Postfächern.

  8. Link verteilen

    • Team: Die Leitung legt die Konten in der App an und gibt die Zugangsdaten mit dem Link weiter.
    • Eltern: einfach den Link schicken oder als QR-Code am Eingang aushängen. Keine Anmeldung nötig – sie sehen nur die Bücherliste.
    • Auf dem Handy: Link öffnen → „Zum Home-Bildschirm“. Dann erscheint die App mit eurem Logo.

B · Updates und Fehler beheben

Eure Daten liegen in Firebase. Ein Update tauscht nur die App-Datei aus – Bücher, Kinder und Ausleihen bleiben erhalten.

  1. Änderung bekommen

    Fehler gefunden oder Wunsch? Beschreibe ihn Claude (in diesem oder einem neuen Chat) und häng die aktuelle index.html an. Du bekommst eine neue index.html zurück.

  2. Alte Version sichern

    Bewahre die bisherige index.html auf deinem Computer auf, z. B. als index-alt.html. Läuft etwas schief, lädst du sie einfach wieder hoch.

  3. Neue Version hochladen

    1. GitHub → euer Repository → „Add file“ → „Upload files“.
    2. Die neue index.html hineinziehen → „Commit changes“. GitHub ersetzt die alte Datei.
    3. Nach 1–2 Minuten ist das Update für alle da. Auf dem Handy die App ggf. einmal schließen und neu öffnen.

    Wichtig: config.js beim Update nicht überschreiben. Ändern sich die Sicherheitsregeln, ersetzt ihr sie wie in Schritt A3.

  4. Selbst eine Kleinigkeit ändern

    Auf GitHub kannst du index.html anklicken und mit dem Stift-Symbol direkt bearbeiten, z. B. einen Text oder eine Telefonnummer. Mit „Commit changes“ speichern. Jede Version bleibt unter „History“ erhalten.

C · Gut zu wissen

Wer sieht was?
Elternohne Anmeldung: Bücherliste mit „im Regal“ / „ausgeliehen“ – keine Namen, kein Verlauf
Teamangemeldet und freigeschaltet: alles, auch die Namen der Kinder
Leitungwie Team, zusätzlich: Kolleg:innen freischalten und entfernen
Das ist in den Sicherheitsregeln der Datenbank festgelegt – nicht nur in der Ansicht. Wer ein Konto hat, aber nicht freigeschaltet ist, sieht nur die Elternansicht.
Kosten: Der kostenlose Tarif von Firebase und GitHub Pages reicht für eine Kita normalerweise locker. Ohne hinterlegte Zahlungsmethode kann auch nichts kosten – im schlimmsten Fall pausiert die Datenbank bis zum nächsten Tag.
Öffentliches Repository: Bei GitHub sind die App-Dateien öffentlich einsehbar. Das ist unbedenklich: Darin stehen keine Kinderdaten, nur der Programmcode und die Projektadresse.
Titelsuche: Beim Scannen schickt die App nur die ISBN-Nummer an Google Books bzw. Open Library, um Titel und Autor:in zu finden – keine Namen.
Passwort vergessen? In der App: „Team-Anmeldung“ → E-Mail eintragen → „Passwort vergessen“. Kommt keine Mail an (Outlook filtert sie gern weg): Die Leitung löscht das Konto in Firebase unter Authentication → Nutzer → ⋮ → „Konto löschen“ und legt es in der App unter „Einstellungen & Team“ mit einem neuen Start-Passwort wieder an. Die Freischaltung bleibt dabei erhalten.
